## 1. Testing Basis & Philosophy

This test strategy establishes an exhaustive verification and quality assurance framework for the entire IdentityCard platform. Testing is conducted strictly against the following core principles:

### 1.1 Network Call & Database Round-Trip Minimization
- **Backend <-> Database:** Every mutation minimizes round trips. All complex inserts, updates, and deletes with dependent state execute in a single round-trip using PostgreSQL Common Table Expressions (CTE) and JSON aggregation builders (`json_build_object`, `COALESCE(json_agg(...), '[]'::json)`), returning the full modified entity directly.
- **Frontend <-> Backend:** Network chattiness is strictly forbidden. The client utilizes TanStack Query caching, optimistic UI updates, proper cache invalidation keys, and avoids duplicate sequential fetches for dependent data.
- **Cache-Aside with Anti-Stampede Jitter:** Read-heavy entities (catalog, pricing, event configs, attendance summaries) are backed by Redis cache using `RememberWithJitter` with $\pm 20\%$ pseudo-random dispersion to prevent cache stampedes (thundering herds).

### 1.2 Generic Architectural Patterns & Standard Process Line
- Every entity and feature in the frontend (`apps/web`, `apps/admin`) adheres to the unified generic pattern:
  - Standard page layout using `<PageHeader />` with title, optional description, badge, and actions.
  - Standard listing and pagination utilizing generic `<InfiniteDataTable />` and `<DebouncedInput />`.
  - Standard confirmation dialogs using `<ConfirmButton />`.
  - Standard form schemas powered by `react-hook-form` + `zod` with central type definitions.
  - Standard React Query hook pattern: `useQuery` / `useMutation` wrappers organized in `query-hooks/<entity>.api.ts`.
- Any entity deviating from this standard pipeline is flagged and refactored.

### 1.3 Anti-Over-Engineering (KISS & YAGNI)
- Eliminate bloated abstractions, redundant wrapper functions, duplicate interfaces, and premature architectural overhead generated by hallucinating AI models.
- Prioritize native browser APIs, standard library functions, and proven, mature third-party libraries instead of maintaining home-grown implementations.
- Proactively prune dead, unreachable, and orphaned code.

### 1.4 Test Suite Isolation Rule
- **Zero test files tolerated within application or logical source trees.** All `*_test.go`, `*.test.ts`, `*.test.tsx`, `*.spec.ts` files reside strictly in the dedicated root `tests/` folder.
- The root `tests/` tree is partitioned into:
  - `tests/server/unit/`: Standalone unit tests for cryptographic operations, algorithms, formatting, and calculations.
  - `tests/server/integration/`: Direct HTTP-level integration tests covering every single API across all domains with live PostgreSQL and Redis.
  - `tests/server/e2e/`: Multi-step operational user journeys covering end-to-end organizer, attendee, scanner, and admin lifecycles.
  - `tests/web/`: Client application component, schema, date/money formatting, CSV, query keys, and offline queue unit tests.
  - `tests/admin/`: Admin console formatting, coupon governance, and client state unit tests.
  - `tests/landing/`: Landing page pricing calculator, interactive quote engine, and metadata tests.

### 1.5 Code Formatting & Style Standards
- Default indentation of **4 spaces** across all files (`.ts`, `.tsx`, `.go`, `.json`, `.md`, `.sql`, `.css`).
- Adherence to the project's preferred TSX conditional rendering format: `{ condition && <div>...</div> }`.

## 2. Core Architectural & Specific Checks

The following mandatory architectural checks are prioritized:

| Check ID | Area | Target Specification |
|---|---|---|
| **CHK-JWT-01** | JWT Session Management | **Inline Token Refresh / Transparent Renewal via Middleware:** Verify that expired access tokens are rotated transparently within middleware (`jwtauth.Authenticate`) using the refresh token, emitting updated `Set-Cookie` headers on the active request without failing or rejecting with 401. |
| **CHK-CACHE-01** | Redis Cache Layer | **Cache Stampede Prevention (Adding Jitter):** Verify `AddJitter` and `RememberWithJitter` enforce $\pm 20\%$ randomized TTL dispersion. Test concurrent access under simulated cache eviction. |
| **CHK-RL-01** | Rate Limiter | **Redis Token Bucket & Backend Rate Limiter:** Verify atomic Lua token bucket script (`tokenBucketScript`), burst capacity, refill rate per client IP, and header propagation (`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `Retry-After`). |
| **CHK-SEAT-01** | Seat Booking & Concurrency | **Seat Booking Concurrency Lock & Queue Evaluation:** Test high-concurrency ticket/seat contention. Compare Redis distributed queue/locking vs. PostgreSQL transaction-level advisory locking (`pg_advisory_xact_lock`) to verify race protection and database connection efficiency. |
| **CHK-CONF-01** | Service Configurations | **Third-Party & Service Configuration Integrity:** Verify correct environment variable binding, fallback defaults, and connection pooling for Razorpay, Resend Mailer, MinIO S3 Object Storage, Google OAuth 2.0 / GSI, and Redis. |

## 3. Comprehensive Test Specifications

### 3.1 Unit Testing Strategy (`tests/server/unit/`, `tests/web/`, `tests/admin/`, `tests/landing/`)

#### Server Unit Tests (`tests/server/unit/`)
1. **`jwtauth_test.go`**: Tests EdDSA / RSA / HMAC token signing, claim extraction, role validation, expiration thresholds, and tampering detection.
2. **`cache_test.go`**: Tests `AddJitter` mathematical dispersion range ($\pm 20\%$), minimum TTL bounds, and graceful cache degradation on nil or failing Redis connections.
3. **`googleid_test.go`**: Tests Google Identity Services token verification with mock certificates and nonce matching.
4. **`id_test.go`**: Tests `GenerateApplicantUserID` formatting (`8-8-8` format: `event_prefix-random_hex-date_stamp`), case-insensitivity, and cryptographic uniqueness across 1,000 generated IDs.
5. **`idcard_test.go`**: Tests A6 printable PDF ID Card generator (`Render`) using dynamic field coordinates, system barcode/QR placeholders, and PDF stream validity.
6. **`imageproc_test.go`**: Tests photo square-cropping and resizing to $600\times 600$ JPEG and signature transparent PNG processing.
7. **`pricing_test.go`**: Tests tiered pricing brackets, unit rates, flat platform fees, and statutory 18% GST calculation with paise-level rounding.
8. **`pricing_coupon_test.go`**: Tests percentage basis points (`percent_bp`) discount calculations, fixed amount caps, minimum subtotal requirements, and invalid coupon rejections.
9. **`qrsign_test.go`**: Tests HMAC-SHA256 applicant QR signing, tamper resistance, and payload parsing.
10. **`rate_limiter_test.go`**: Tests client IP extraction across reverse proxy headers (`X-Forwarded-For`, `X-Real-IP`, `RemoteAddr`) under trusted proxy CIDR configurations.
11. **`sites_test.go`**: Tests static zip file validation for custom event websites (verifying index.html presence, asset size limits, and zip-slip path traversal prevention).

#### Web Frontend Unit Tests (`tests/web/`)
1. **`money.test.ts`**: Tests formatting currency amounts from paise to rupees, handling whole amounts, fractional paise, and localized digit grouping.
2. **`date-utils.test.ts`**: Tests local date key formatting (`YYYY-MM-DD`), month keys, inclusive multi-day ranges, schedule overrides, and 12-hour AM/PM conversions.
3. **`csv.test.ts`**: Tests RFC 4180 CSV parser and serializer, handling quoted commas, escaped quotes, header normalization, and object array conversions.
4. **`query-keys.test.ts`**: Tests central React Query key factory consistency across auth, credits, events, forms, applicants, and attendance.
5. **`form-builder.test.ts`**: Tests form definition schema validation: enforces mandatory system fields (`name`, `email`, `phone`), catches duplicate field keys, and restricts photo/signature uploads to 1 per form.
6. **`attendance-state.test.ts`**: Tests offline scanner queueing, pending sync counters, batch reconciliation, and attendee punctuality evaluation against scheduled start times.

#### Admin & Landing Unit Tests (`tests/admin/`, `tests/landing/`)
1. **`admin-format.test.ts`**: Tests administrative date range formatters, transaction ledger currency representations, and UTC date converters.
2. **`admin-state.test.ts`**: Tests admin session handling, coupon creation payload validation (basis points conversion, negative subtotal checks), and client filter predicates.
3. **`pricing-calculator.test.ts`**: Tests landing page pricing calculator inputs and metadata formatting.
4. **`quote-engine.test.ts`**: Tests interactive pricing quote calculation: base attendee tiers, sub-events addons, custom branding, custom website addons, promotional discount deduction, and GST calculations.

### 3.2 Integration Testing Strategy (`tests/server/integration/`)

All integration tests execute against live PostgreSQL 17 and Redis 7 instances via `testhelper.SetupHarness(t)`:

1. **`auth_integration_test.go`**: Tests transparent inline session renewal via middleware when access token expires.
2. **`rate_limiter_integration_test.go`**: Tests Redis atomic Lua script token bucket: verifies burst consumption, rate headers (`X-RateLimit-Limit`, `X-RateLimit-Remaining`), HTTP 429 response, and `Retry-After`.
3. **`seat_concurrency_test.go`**: Tests high-concurrency ticket/seat contention under synchronized burst traffic, verifying zero overbooking.
4. **`api_auth_test.go`**: Tests client authentication API endpoints: `/api/v1/auth/google`, `/api/v1/auth/me`, `/api/v1/auth/logout`.
5. **`api_pricing_credits_test.go`**: Tests `/api/v1/pricing/catalog`, `/api/v1/pricing/quote`, `/api/v1/credits`, and `/api/v1/credits/trial` (including duplicate trial claim prevention).
6. **`api_events_dates_test.go`**: Tests event creation, listing, metadata updates (`PATCH /api/v1/events/:id`), dates override with time slots (`POST /api/v1/events/:id/dates/override`), and deletion.
7. **`api_forms_applicants_test.go`**: Tests global form templates, event form creation and locking, schema extraction, applicant registration under credit quota, duplicate registration prevention (409 Conflict), bulk upload, CTE paginated listing, signed QR retrieval, and dynamic PDF ID Card generation.
8. **`api_applyflow_test.go`**: Tests public registration flow: unauthenticated state (`signed_in: false`), applicant session issuance, auto-saving application drafts (`PUT /draft`), confirming submission (`POST /submit`), and organizer fee/draft endpoints.
9. **`api_devices_attendance_test.go`**: Tests scanner device creation, pairing PIN generation, event device assignment, PIN verification (`POST /devices/verify`) yielding `X-Device-Token`, scanner device status, QR scanning, entry recording, duplicate entry prevention, exit recording, and real-time attendance analytics.
10. **`api_subevents_sites_payouts_test.go`**: Tests sub-events creation, settings updates, applicant enrollment, custom website subdomain checking/claiming, organizer Razorpay payout account retrieval, and public contact form submission (including spam honeypot trap).
11. **`api_admin_test.go`**: Tests platform admin authentication (`POST /auth/login`), dashboard metrics, client listing, client suspension with immediate session kill, client unsuspension, catalog inspection, ledger transactions, and promotional coupons CRUD.

### 3.3 End-to-End (E2E) Testing Strategy (`tests/server/e2e/`)

1. **`e2e_organizer_lifecycle_test.go`**:
   - Complete organizer journey from signup -> claiming trial credit -> multi-day event creation -> custom dates and time slots -> form creation with custom fields -> locking form to open registration -> registering VIP and bulk cohort -> enrolling in sub-event workshops -> testing website entitlement gating -> generating PDF ID Cards -> closing registration window -> publishing cards.
2. **`e2e_applicant_scanner_journey_test.go`**:
   - Complete attendee & scanner device journey: public form state discovery -> Google sign-in -> draft answers auto-save -> submission and confirmation -> signed QR token delivery -> gate scanner device PIN pairing -> entry gate scan and check-in -> duplicate entry rejection -> checkout at exit gate -> real-time attendance metrics update in organizer dashboard.
3. **`e2e_platform_governance_test.go`**:
   - Complete platform administration & security journey: admin login -> platform health and revenue dashboard review -> promotional coupon creation -> client organization inspection -> immediate client suspension -> active session token revocation check -> compliance review completion and client unsuspension -> coupon cleanup.
